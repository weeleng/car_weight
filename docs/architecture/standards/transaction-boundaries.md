# C-05 事务边界

## 适用范围

INGEST、BUSINESS、TRACK 三个逻辑数据库，以及跨边界发布和消费流程。

## 已确认约束

| 逻辑数据库 | 职责 |
| --- | --- |
| INGEST | 设备原始事件与接入存证 |
| BUSINESS | 正式业务数据、称重结果与计费 |
| TRACK | 车辆定位与轨迹 |

1. INGEST 原始事件与对应 Outbox 在同一本地事务提交。设备成功 L2 ACK 的时点见 [ACK 与持久化](iot-ack-and-durability.md)。
2. Outbox Relay 负责可靠投递，使用 RabbitMQ Publisher Confirms 确认发布。
3. BUSINESS Inbox、正式业务记录、业务 Outbox 在同一本地事务提交。消费者在业务事务成功提交后确认消息。
4. 使用数据库唯一约束及业务幂等键控制重复处理。数据库结构变更使用版本化迁移。

## 禁止事项

不得依赖跨逻辑数据库的分布式原子事务，不得跨逻辑数据库建立外键，不得使用 Redis 锁作为唯一幂等保障，不得在 BUSINESS 事务成功提交前确认消费。

## 验证要求

验证两个本地事务在任一步骤失败时的回滚一致性。测试发布确认丢失、重复投递、并发消费和提交后重投，确认唯一约束和业务幂等键可防止重复副作用。检查迁移及外键范围。
