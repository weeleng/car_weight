# C-02 时间规范

## 适用范围

设备事件、接入服务、Java 业务代码、数据库、API 和业务展示中的绝对时间。

## 已确认约束

- 设备事件时间使用 Unix Epoch 毫秒。Java 业务代码统一使用 `Instant` 表达绝对时间。
- MySQL 绝对时间字段使用 `DATETIME(3)`，按 UTC 约定写入和解释。该字段类型不保存时区。
- API 时间使用包含偏移量或 UTC 标识的 ISO 8601 格式。业务展示默认使用 `Asia/Shanghai`，允许按项目配置。
- 分别记录设备事件时间、服务器接收时间和数据库持久化时间。保留设备时间质量信息，使时钟异常可识别，并避免用异常设备时间错误排序。

## 禁止事项

不得混用三个时间语义，丢弃设备时间质量信息，或依赖应用进程、JDBC 驱动和数据库的隐式默认时区。

## 验证要求

测试 JDBC 时区、MySQL 会话时区和 API 序列化的实际行为。验证同一 `Instant` 经写入、读取和 API 往返仍代表同一绝对时间，保留毫秒精度。在非 UTC 展示设置及设备时间异常场景检查展示和排序。

## 来源与待核验内容

来源为 ENG-001B-01 提供的 C-02。时间质量字段、异常判定阈值、排序回退规则以及各环境的具体时区配置待核验。
