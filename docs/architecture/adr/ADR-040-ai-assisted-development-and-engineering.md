## 背景

AI 辅助工作要限制范围、来源和权限，并给出可复核证据。设计、实施、验收与发布分别授权。

## 决策

| 角色 | 候选职责 |
| --- | --- |
| 项目负责人及人工审核者 | 确认需求、审批架构与任务、审查变更、决定合并及批准生产发布 |
| ChatGPT | 需求、架构和选型、ADR/ACR 规划、任务拆分、GitHub 只读核查、审查、风险和验收设计。按现行协作约定不写仓库、不建分支、不推送、不建 PR、不合并 |
| Codex | 读取约束、按任务建分支、实施及测试、执行获准验证、提交推送、权限允许时建 Draft PR，输出证据 |
| GitHub | 版本及分支、PR、审查、CI 和变更追溯 |

- ADR 记录背景、取舍、约束及验证，ACR 记录正式变更和影响。均注明编号、版本、状态、来源、范围、模块、关联、验证及批准记录。Proposed 为候选。任务与正式约束冲突时停止相关变更并报告。
- 任务注明编号、目标、目标分支、起始 SHA、任务分支、前置阅读、可改和禁止范围、技术约束、验证及交付物。小范围单一目标，避免混入无关重构。目标为 master-jdk17，任务分支候选 docs/、feat/、fix/、test/、refactor/、chore/。核对基线偏移后按授权处理。
- 提交关联任务、明确目的及合理粒度。PR 记录目标、起止 SHA、文件、实现说明、关联 ADR/ACR、实测及未执行、风险、数据库、部署和回滚。API Forbidden 提供比较页面。人工审查决定合并，禁止自动合并。候选保护规则为禁止关键分支直推、强制 PR 及必要 CI、至少一名授权审核者、限制强推及按需限制删除。
- 验证分文档、静态、编译、单元、集成、数据库、消息、模拟、真机、安全、性能、灾备和用户验收。分别记录 Codex 自检、ChatGPT 独立只读核查、实际 CI 和人工验收，附命令、结果、失败和待验证、PR 或比较页。
- Java 按 JDK 21、Java 17、Reactor、API/Biz 边界、无循环、事务、异常、脱敏和测试校验。数据库校验 UTC、重量精度、唯一键、事务、Outbox/Inbox、版本化迁移、历史兼容、租户、索引和恢复。
- IoT 变更记录版本、帧、字节序、类型、CRC 和认证、身份、ACK、重试、补传、双向兼容、错误和测试向量。后续模拟器覆盖 660L、240L、未知 RFID、异常重量、缺定位、重复、同身份异载荷、乱序、重启、ACK 丢失、离线、非法身份、完整性、断网和突发流量，采用独立测试身份及凭据。
- AI 与人工代码同标准，查不存在的 API、依赖、事务、测试证据、权限、泄露、密钥、密码学、异常、无界重试、丢失及计费防重。合成或脱敏数据优先，工具权限最小。新依赖记录用途、版本、来源、许可证、风险、维护及兼容。上游独立任务评估安全、依赖、API、数据库、模块及冲突。

## 适用范围

研发约束、任务、分支、交付、验证、上游同步与发布审批。

## 约束与禁止事项

禁止将 Proposed 当作批准或伪造历史与验收，禁止未经批准改架构、直推关键分支、强推覆盖他人、提交临时配置或凭据。禁止删校验以过编译、绕过版本迁移改生产库、改变 ACK 持久化或引入远程危险机械控制。禁止向未授权 AI 提供生产密码、Token、密钥、私钥、外部凭据、未脱敏个人和客户数据。禁止以编译代替功能、以模拟代替硬件验收，禁止 AI 自动合并及发布。保护规则由负责人配置，本任务不改设置。

## 备选方案及取舍

集中一次性大任务减少交接，但难以定位变更和风险。采用可独立验证的小任务，保留人工跨项审核。
