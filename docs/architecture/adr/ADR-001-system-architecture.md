# ADR-001 系统总体架构

- 状态：`Proposed`
- 版本：草案 v0.1

- 本次起始基线：`3f831747a7fe0c72b8906366caa26f0145884788`

## 决策来源

ENG-001B-02B-01 提供系统范围、分阶段建设及交付模式的拟议结论。[C-01](../standards/technology-baseline.md)和[C-06](../standards/module-boundaries.md)记录既有架构约束。[九模块映射报告](../../engineering/module-mapping.md)为物理划分提供建议。

## 背景

车载称重平台需要将设备接入、正式业务处理、计费、GIS 轨迹、统计分析与外部集成划清边界，并在初期控制部署与事务复杂度。仓库已有 RuoYi-Vue-Pro 后端与独立 Gateway 构件。

## 决策

- 基于 RuoYi-Vue-Pro 建设城市环卫车载称重与运营管理平台。Spring Boot 后端采用模块化单体，IoT Gateway 独立部署，承担设备接入。称重、计费等正式业务由后端负责。
- 按 C-06 的九个逻辑模块组织业务。物理 Maven 映射以 C-06 记载的建议及后续审批为准。
- 跨模块通过公开 API 或业务事件交互。GIS 轨迹、统计分析与外部集成经各自的公开契约与业务协作。
- 分阶段建设，避免初期引入非必要的分布式微服务。支持 SaaS 与私有化部署，具体方案由专项 ADR 确定。

## 适用范围

后端业务组织、设备接入边界、跨模块依赖及部署形态。

## 约束与禁止事项

禁止直接依赖其他模块的 Mapper、DO 或内部 Biz 实现，禁止循环依赖。本次只交付草案。

## 备选方案及取舍

将所有能力放在同一进程可简化部署，但设备连接与业务处理将共享故障域。全面微服务可独立扩缩容，但会增加跨服务调用和一致性成本。拟保留模块化单体，并独立部署连接生命周期不同的 Gateway。

## 与其他 ADR/ACR 的关系

[C-01](../standards/technology-baseline.md)约束架构和部署，[C-06](../standards/module-boundaries.md)约束模块边界。拟与 ADR-002 的技术选型、ADR-006 的数据库边界及 ADR-012 的接入边界配套。[ACR-001 核对记录](../acr/ACR-001-reconciliation.md)提供约定出处，历史依赖关系待核验。

## 验证要求

实施后核查模块依赖图、公开契约及循环依赖，验证 Gateway 可独立部署且连接负载与业务后端隔离。SaaS 与私有化部署须按获批方案分别验收。本次未执行上述运行验证。

## 待确认事项

物理 Maven 划分、各阶段交付顺序、SaaS 租户隔离与私有化部署拓扑待确认。
