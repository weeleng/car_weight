# ADR-018 商户及垃圾产生责任主体管理

## 状态与版本

- 状态：`Proposed`
- 版本：草案 v0.1
- 起始基线：`e7c025f623191928633dfc843c070e38d1cb4bca`
- 编号、标题和设计要点来自 ENG-001B-02C-01，候选映射与历史批准原文待核验。

## 决策来源

ENG-001B-02C-01 提供主体、服务点和计费责任的拟议模型。[ADR-016](ADR-016-rfid-identification.md)规定 RFID 识别和历史归属，[ADR-024](ADR-024-contract-and-billing.md)规定正式记录及计费资格边界。

## 背景

垃圾产生主体用于溯源、服务及计费，可为个体工商户、企业、事业单位或其他获准主体。商户是其中一种类型，产生地点与合同付款方可能不同。

## 决策

- 分离责任主体、登录用户、租户及付款方的逻辑身份。按类型和实际需要保留内部标识、名称、主体类型、适用身份信息（如统一社会信用代码）、联系方式、经营或服务地址、服务项目与服务状态、垃圾类别及关联场所或服务点。不适用的身份字段不强制采集。
- 一个主体可关联多个经营场所或收集服务点。服务点有地址、空间位置、项目、垃圾类别、有效服务关系及必要的收集和清运配置。主体档案与项目服务关系分离，可关联多个项目。
- 每主体可绑定多个 RFID 标签。标签 UID 独立，绑定有有效期及历史，同有效范围和时间内无歧义。支持启停、更换和重绑。P0 无需独立垃圾桶资产档案。
- 正式称重可追溯实际产生主体、服务点、运营项目、有效 RFID 绑定、合同或收费规则及计费责任主体。物业代收、统一清运等代理付款须有明确授权和合同关系。
- RFID 未绑定、主体不存在、服务关系失效或归属冲突时，保留原始称重事件并记录异常。允许人工补充归属，记录操作人、时间和依据。主体更名、地址变化、重绑、项目或合同调整后，仍能追溯作业时点的关系及必要历史属性。

## 适用范围

主体与服务点档案、项目服务关系、标签绑定、称重归属、计费责任和历史审计。

## 约束与禁止事项

遵守个人信息最小必要原则。禁止假定主体、用户、租户和付款方共用 ID 或一对一。禁止由标签推导或信任客户端提交的商户 ID，禁止依据相同信用代码自动共享跨租户数据。未知或冲突时禁止自动创建主体、计费或覆盖原始事件。禁止按当前配置静默改写历史称重及账单。

## 备选方案及取舍

统一档案可减少重复录入，但跨租户共享需要明确授权和隔离。先区分主体、服务关系与付款关系的逻辑边界，物理模型待专项确认。

## 与其他 ADR/ACR 的关系

项目关系见 [ADR-004](ADR-004-organization-and-project.md)，垃圾桶资产边界见 [ADR-017](ADR-017-asset-and-device-management.md)。沿用 ADR-016 的历史绑定与 ADR-024 的计费资格。隐私采集、保留及脱敏关联候选 [ADR-030](README.md#adr-030)，正文待导入。适用 C-02、C-03、C-05、C-06，出处见 [ACR-001 核对记录](../acr/ACR-001-reconciliation.md)。

## 验证要求

后续覆盖多服务点、多标签、重绑、迟到称重、主体停用和更名、服务失效、未知标签补录、代理付款、跨项目及跨租户越权和历史称重及账单追溯。

## 待确认事项

服务点共享收集设施及计量规则、RFID 与主体和服务点的关联粒度、跨租户档案去重与共享、个人信息处理，以及历史快照和版本化方式待确认。
