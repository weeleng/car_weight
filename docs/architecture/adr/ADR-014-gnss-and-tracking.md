# ADR-014 GNSS 定位与轨迹管理

## 状态与版本

- 状态：`Proposed`
- 版本：草案 v0.1
- 起始基线：`65af9b997071ff3a0e63c289b5ce33fd191d2696`
- 编号、标题及历史设计要点由 ENG-001B-02B-02 提供，候选映射及历史批准原文待核验。

## 决策来源

ENG-001B-02B-02 提供定位顺序、轨迹和作业位置关联的拟议要点。[ADR-006](ADR-006-database-architecture.md)、[C-02](../standards/time-conventions.md)和[C-05](../standards/transaction-boundaries.md)分别约束持久化边界和时间。

## 背景

主定位可能无效或过期，且 Android 与 PDA 对应不同部署形态。离线补传可能使收到的点晚于作业事件。

## 决策

- 定位优先顺序为控制板 GNSS、Android 车载终端、PDA。MCU GNSS 为主要来源，无效或超出有效时间窗口时回退到当前可用业务终端。三种来源无需同时在线。
- 记录设备与车辆身份、定位来源、定位时间、服务器接收时间、经纬度、有效状态、坐标系、定位质量及可用的速度和方向。按 C-02 区分持久化时间，存储绝对时间使用 UTC 语义的 `DATETIME(3)`。
- 区分 GNSS 原始坐标、地图供应商坐标和业务空间计算坐标。坐标转换规则留待 ADR-010 专项确定。
- 原始事件在 INGEST 存证，正式定位轨迹归 TRACK。TRACK 独立幂等写入并支持失败恢复。拟采用按月分区。
- 作业称重关联发生时的位置。定位无效时保留称重事件，标记缺失或异常，并按后续业务规则决定是否人工核验。

## 适用范围

定位来源、轨迹采集与存储、称重位置关联。

## 约束与禁止事项

禁止用展示坐标覆盖原始坐标，禁止用迟到的最新点静默覆盖历史作业位置。禁止因 GNSS 无效删除称重事件，禁止依赖 INGEST 与 TRACK 跨库原子事务。

## 备选方案及取舍

单一来源便于解释但降低故障时的可用性。允许回退需要保留来源与质量。按月分区有利于按时间归档，实际分区键和保留周期须结合查询验证。

## 与其他 ADR/ACR 的关系

遵循 ADR-006、C-02、C-05，与 [ADR-015](ADR-015-weighing-model.md)共享作业时间语义。[ADR-010](README.md#adr-010)是尚待导入的候选依赖。约定来源见 [ACR-001 核对记录](../acr/ACR-001-reconciliation.md)。

## 验证要求

后续覆盖定位失效、漂移、来源切换、乱序、重复点、离线补传、坐标转换与跨库处理失败。

## 待确认事项

上报周期、静止与运动上报策略、有效窗口、质量阈值、补传及乱序、来源切换、位置关联窗口、转换规则、分区键、索引、保留周期与归档待确认。
