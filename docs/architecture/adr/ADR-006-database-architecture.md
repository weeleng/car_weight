# ADR-006 数据库架构

## 状态与版本

- 状态：`Proposed`
- 版本：草案 v0.1
- 编号与标题为 ENG-001B-02B-01 提供的候选映射，原始 ADR 正文尚未核验。历史版本与完整批准原文待取得。
- 本次起始基线：`3f831747a7fe0c72b8906366caa26f0145884788`

## 决策来源

ENG-001B-02B-01 提供三个逻辑 MySQL 数据库及数据归属。[C-02](../standards/time-conventions.md)、[C-03](../standards/weight-conventions.md)和[C-05](../standards/transaction-boundaries.md)记录既有约束。

## 背景

设备原始事件、正式称重和计费、定位轨迹具有不同写入和留存语义。跨边界消息可能重复投递，接入存证须保持可追溯。

## 决策

| 逻辑 MySQL 数据库 | 数据归属 |
| --- | --- |
| INGEST | 设备原始事件、接入存证及对应 Outbox |
| BUSINESS | 正式业务、称重、合同、计费及业务 Inbox/Outbox |
| TRACK | 车辆定位及轨迹 |

INGEST 原始事件和对应 Outbox 在同一本地事务提交。BUSINESS Inbox、正式业务数据和业务 Outbox 在同一本地事务提交。使用数据库唯一约束和业务幂等键防止重复处理。

## 适用范围

数据归属、事务与幂等边界、时间与重量类型及版本化迁移。

## 约束与禁止事项

- 禁止依赖跨逻辑数据库的分布式原子事务及建立跨库外键。正式业务修正不得覆盖原始事件。
- 按 C-02 使用 UTC 语义的 `DATETIME(3)` 保存绝对时间。按 C-03 区分协议有符号 INT32 克、业务 BIGINT 克和正式 DECIMAL(12,3) 千克。
- 数据库结构使用版本化迁移。本次不生成 SQL 迁移文件。

## 备选方案及取舍

共享事务域可简化原子写入，但会耦合原始事件、业务和轨迹。三个逻辑库与本地事务明确所有权，跨边界需要投递、重试和去重。逻辑划分允许另行比较同实例与分实例方案。

## 与其他 ADR/ACR 的关系

适用 C-02、C-03、[C-04](../standards/iot-ack-and-durability.md)与 C-05。拟支撑 ADR-012 的接入可靠性，并与 ADR-008 的时间和重量契约衔接。[ACR-001 核对记录](../acr/ACR-001-reconciliation.md)提供约定出处。

## 验证要求

在 MySQL 8.4 验证空库与存量迁移、UTC 和毫秒精度、精确重量往返、事务回滚、并发重投及唯一键约束。检查原始事件未被覆盖以及不存在跨逻辑库外键。本次未执行运行验证。

## 待确认事项

物理数据库部署、表结构、唯一键列、迁移工具集成、归档与分区策略待确认。
